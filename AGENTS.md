# Working rules for Team 10

- Use Atharv as the Git author and committer name. Keep the existing local Git email. Check both names before pushing. Do not add an assistant as a coauthor. Keep the original team's commits unchanged.
- Keep code, comments, README text and commit messages plain and easy for a student to explain. Prefer short functions and clear names. Explain technical terms when needed. Do not invent contributions or test results.
- Run an independent verification agent in parallel for every change. It must review the final changes and run useful checks before reporting completion. Resolve its findings and check again when needed.
- Use the project opened in VS Code for edits, tests and Git work. Run commands in its integrated terminal. The verification agent may use separate read-only tools and isolated test databases.
- Work one assignment step at a time. Explain what changed, what was checked and what is still pending.
